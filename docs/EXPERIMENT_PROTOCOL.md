# RobustSense 冻结实验协议

## 冻结边界

本协议于 2026-09-10 冻结，早于任何 `ablation_dev`、`credible` 或 `full` 测试 run。Phase 2 至 Phase 4 的 fold 0 开发指标当时已经可见，但它们仅用于验证流水线，未用于选择种子、测试阈值、fold、标签或有利故障场景。可信实验的优化器以及 80 epoch/10 patience 预算均为预先声明的项目默认值。

机器可读的权威文件是 `configs/experiment/phase5_plan.yaml`。首个 Phase 5 命令会对全部协议输入计算哈希并写入 `reports/phase5_protocol_lock.json`；之后若不匹配则停止运行。任何修改都必须通过明确的 ADR 说明是否使既有 run 失效，然后创建新协议版本和新锁，不允许直接覆盖配置。

## 冻结数据合同

- 数据集：ExtraSensory 官方逐用户预计算特征版本。
- 任务：15 标签多标签分类；标签 `NaN` 表示未知，不计入损失和指标。
- 输入：Phase 1 清单中经审计的 177 特征、六模态模式。
- 外层 fold `f`：官方 fold `f` 用作测试，官方 fold `(f + 1) mod 5` 用作验证，其余三个 fold 用作训练。
- 预处理、类别权重和早停只使用训练/验证数据；每个 fold 的中位数/IQR 预处理器仅由该 fold 的训练用户拟合。
- 自然缺失评估包含所有合法测试行；受控实验在同一 fold 内为每个模型使用相同的六模态完整测试 ID。

标签顺序原样写入机器可读计划。模式或标签哈希不匹配均为致命错误。

## 冻结训练与模型矩阵

可信矩阵使用五个官方 fold、种子 13 和十二个模型：六个 B0 单模态变体、B1 线性早期融合、B2 MLP 早期融合、B3 后期融合、B4 门控融合、B5 鲁棒门控融合及 P 质量感知融合。最大预算为 80 epoch，批量大小 512，AdamW 学习率 0.001，权重衰减 0.0001，梯度裁剪 5.0，并以阈值 0.5 的验证 Macro-F1 执行 patience 为 10 的早停。

只有全部可信单元成功后才能运行 `full` 扩展。该扩展为 B4、B5 和 P 增加种子 29 与 47，并在独立注册的 full 配置中保留种子 13。不得根据测试性能选择种子。

## 冻结阈值与评估规则

- 每个标签在 0.05–0.95、步长 0.05 的固定网格上按验证 F1 选择一个阈值。
- 保存的验证阈值不作修改，用于自然缺失和全部受控测试场景；同时保留固定 0.5 的结果作为透明性检查。
- 受控故障族和强度严格采用 `configs/corruption/eval.yaml`；噪声应描述为标准化特征空间污染，不得描述为物理硬件噪声。
- 主要指标为已知标签上的 Macro-F1、Micro-F1 和 mAP。聚合时 `NaN` 仍为 `NaN`，不得转为零。
- 报告 fold 均值和样本标准差。在 full 扩展中，先在 fold 内聚合种子，再聚合 fold。

## 冻结 A1–A5 开发筛查

在 fold 0、种子 13 和统一三 epoch 预算下，以 A0（完整 P）对比：

- A1：仅禁用 Sensor Dropout，保留特征噪声增强和两个辅助项。
- A2：仅禁用特征噪声增强，保留 Sensor Dropout 和两个辅助项。
- A3：移除显式质量特征；ReliabilityNet 和门控只接收内容输入。
- A4：移除 ReliabilityNet 及全部显式质量输入，仅保留内容门控；可靠度损失必为零，一致性仍启用。
- A5：仅将可靠度辅助损失权重设为零；保留架构、污染、质量输入和一致性损失。

A0–A5 只属于开发证据，不是五折因果结论。最终报告若要对某项核心消融作出结论，必须在不改变定义的前提下注册并运行全部五折。

## 运行治理

`reports/run_registry.csv` 保存每个注册单元及当前状态。`reports/run_attempts.csv` 在逻辑上只追加并保留每次尝试；完整 stdout/stderr 存放在 `runs/_phase5_logs/`。普通调用只运行 `pending` 单元，`--retry-failed` 只运行失败单元。成功单元绝不会被无声重跑；此前中断的 `running` 单元会先以明确原因转为 `failed`，之后才允许重试。

只有当注册表显示冻结配置中的每个单元均成功，且评估完整性验证器接受全部 run 产物后，才能生成最终报告。
