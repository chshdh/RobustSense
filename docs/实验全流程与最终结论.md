# RobustSense 实验全流程与最终结论

## 1. 一句话说明项目

RobustSense 是一个面向多源移动感知的多标签上下文识别项目。它研究手机、手表、位置、
音频和设备状态等模态在自然缺失、人工污染或长期故障时，模型如何进行质量感知融合、
可靠度估计、选择性预测和风险控制。

项目最终没有把重点放在“制造一个更高的单点准确率”，而是完成了一条可复核的研究链：

1. 建立无泄漏的用户独立五折基线；
2. 加入质量特征、可靠度、任务效用与拒绝机制；
3. 验证可靠度能否直接代表预测错误风险；
4. 分离连续风险控制与错误告警两种业务目标；
5. 进行最后一次标签级融合优化，并依据预注册标准决定是否发布。

最终发布决策是：**保留 P2 作为默认研究模型，使用 V3-4 的 `risk_control` 作为可选决策层；
不把 P2-LC 升级为默认模型。**

## 2. 数据、输入和任务

### 2.1 数据集

- 数据：ExtraSensory 官方预计算特征；
- 用户数：60；
- 样本数：377,346；
- 工程模态：6 个；
- 输入特征：177 维；
- 输出标签：15 个非互斥活动或情境标签。

六个模态分别是：

1. 手机加速度；
2. 手机陀螺仪；
3. 手表加速度；
4. 位置；
5. 音频；
6. 手机状态。

任务是多标签分类，因此每个标签独立使用 sigmoid，不能使用单一 softmax。标签中的 `NaN`
代表未知，不是负例；未知标签不进入损失，也不进入指标分母。

### 2.2 用户独立五折

每个外层 fold 都使用互不重叠的用户：

- 当前 fold：test；
- 下一个 fold：validation；
- 其余三个 fold：train。

这保证同一个用户不会同时出现在训练和测试中，评估的是对新用户的泛化，而不是记住个人模式。

### 2.3 防止数据泄漏

以下内容必须在每个 fold 内仅使用训练用户拟合：

- 特征中位数；
- IQR 稳健缩放参数；
- 异常值与质量统计基准；
- 类别正权重。

validation 只负责早停、模型选择、逐标签分类阈值和拒绝阈值。test 只在模型、阈值和协议冻结后
由独立评估过程打开，不能用于调参或选择最好结果。

逐标签阈值在 validation 上从 0.05 到 0.95、步长 0.05 搜索 F1 最优值。不同标签流行率差异
很大，因此不能简单地统一使用 0.5。

## 3. 五维质量特征

每个模态都从当前输入计算五个质量量，不需要在推理时知道人工故障类型：

| 质量量 | 含义 | 典型解释 |
|---|---|---|
| 是否可用 | 当前模态是否至少存在有效观测 | 完全缺失时为 0 |
| 特征观测比例 | 该模态有效特征数占总特征数的比例 | 越低表示缺失越严重 |
| 异常值比例 | 超出训练集稳健范围的特征比例 | 越高表示可疑值越多 |
| 稳健标准分绝对值均值 | 相对训练中位数和 IQR 的平均偏离 | 表示整体漂移程度 |
| 稳健标准分绝对值最大值 | 最大单特征偏离 | 捕捉局部极端异常 |

这些值描述的是“当前输入看起来是否完整、是否偏离训练分布”，不是人工故障标签，也不是模型
是否预测正确的直接答案。

## 4. 模型演进

| 名称 | 核心结构 | 解决的问题 | 最终定位 |
|---|---|---|---|
| B4 | 内容编码 + 模态门控 | 学习各模态对任务的贡献 | 普通门控基线 |
| B5 | B4 + Sensor Dropout + 训练期污染 | 增强缺失和污染鲁棒性 | 分类强基线 |
| P | B5 + 五维质量 + ReliabilityNet | 将输入质量显式送入门控 | V1 质量感知模型 |
| P2 | 独立 utility 与 reliability，可靠度显式约束权重 | 分离“有用性”和“可信性”，支持拒绝 | 最终默认研究模型 |
| V3 决策层 | 冻结 P2 后学习选择性预测和业务策略 | 控制已接受样本风险或发现错误 | `risk_control` 可选使用 |
| P2-LC | 每个标签拥有独立的模态 utility | 检验标签级路由能否提高主终点 | 最终未发布 |

P2 的融合公式为：

```text
score_i = utility_i + β × log(reliability_i + ε)
weight_i = masked_softmax(score_i)
system_reliability = Σ_i weight_i × reliability_i
```

其中 utility 表示模态对当前分类任务的贡献，reliability 表示模态当前可信程度。不可用模态
权重严格为 0；全部模态不可用时失败关闭。

## 5. 故障与评估场景

项目同时保留两条评估线：

1. 自然缺失：直接使用真实测试样本原有的模态缺失模式；
2. 受控故障：从完整模态样本出发，注入确定性的特征空间故障。

受控评估包括：

- 63 种非空模态组合；
- Gaussian 噪声；
- 偏置漂移；
- 尺度错误；
- “移除一个模态 + 污染另一个模态”的 60 种混合故障；
- 长度 5、15、30 的持续缺失或持续噪声 episode。

这些故障发生在标准化预计算特征空间，不能描述成真实加速度计损坏、GPS 多径或麦克风物理故障。

## 6. 按实际进度完成的阶段

### 6.1 V1：从数据审计到完整可信矩阵

#### Phase 0：环境与项目骨架

- 建立 Windows 原生开发环境；
- 验证 Python 3.12、PyTorch CUDA 12.8 和 RTX 2060；
- 建立配置、命令行、测试和报告目录。

#### Phase 1：数据审计

- 审计 60 名用户和 377,346 个样本；
- 验证标签只能为 0、1 或 `NaN`；
- 拒绝重复 `(user_id, timestamp)`；
- 验证官方用户 fold 隔离；
- 根据真实表头建立六模态切片。

#### Phase 2–3：基线和质量感知模型

- 完成单模态、早期融合、后期融合、B4、B5、P；
- 实现 masked weighted BCE；
- 实现 Sensor Dropout、训练污染、可靠度辅助损失与一致性损失；
- 保存 checkpoint、验证阈值、预测、质量、可靠度和权重诊断。

#### Phase 4–5：注册评估

- 完成冻结的 5 折正式矩阵 60 个单元；
- 完成 6 个仅用于开发的短消融单元；
- 二者不能合并表述成“66 个正式五折实验”。

V1 的主要结果为：

- 受控完整模态 Macro-F1：B5 最高，0.6043；
- 自然缺失 Macro-F1：P 最高，0.5781；
- P 相对 B4 提升约 0.0110，并在 5/5 个外层 fold 胜出；
- 随机移除三个模态时，P 平均相对下降 9.45%，B4 为 12.87%。

#### Phase 6–7：演示、材料与审计

- 完成真实 checkpoint 的 Streamlit 离线回放；
- 完成技术报告、模型卡、数据卡、答辩问答、口头稿和一页摘要；
- 完成 60/60 正式 run 完整性审计；
- 按项目要求不制作 PPT，也不重新创建虚拟环境。

### 6.2 V2：可靠度约束融合 P2

#### V2-0：冻结 V1

- 冻结 813 个 V1 权威文件；
- 建立 V2 独立命名空间；
- 测得训练 step 中约 73.65% 时间花在 CPU 污染构造上，确认 GPU 并未失效。

#### V2-1：P2 最小实现

- 将 task utility 与 input reliability 分开；
- 用 `β log(r + ε)` 显式约束融合权重；
- 增加可靠度排序损失；
- 增加 validation 冻结的拒绝阈值；
- test 不在训练进程中打开。

#### V2-2：性能优化

- 为污染等价性建立测试；
- 将逐样本 CPU 污染改为保持数值语义一致的向量化实现；
- 使用并行任务提高整体吞吐；
- 不根据模型成绩调整并行策略。

#### V2-3：消融与方案选择

- 比较分类、可靠度、排序、一致性等组件；
- 使用开发消融确定 V2-4 方案；
- 开发消融不作为正式五折因果证据。

#### V2-4：多种子正式实验与压力测试

- 核心矩阵：4 个模型 × 5 个 fold × 3 个 seed，共 60/60；
- 扩展矩阵：60/60；
- 所有阈值仍来自 validation；
- 统计先在同 fold 内平均三个 seed，再等权平均五个 fold。

自然缺失结果：

| 模型 | Macro-F1 |
|---|---:|
| B4 | 0.565135 |
| B5 | **0.578605** |
| P | 0.576678 |
| P2 | 0.577684 |

P2 相对 P 的用户级配对 Bootstrap 均值为 +0.001184，95% 区间为
[-0.001732, 0.004345]，区间跨 0。因此不能声称 P2 在自然缺失主终点上稳定显著领先。

扩展场景结果：

| 场景 | B4 | B5 | P | P2 | 最佳 |
|---|---:|---:|---:|---:|---|
| 63-mask 平均 | 0.485345 | **0.517801** | 0.516258 | 0.516783 | B5 |
| 混合故障平均 | 0.544741 | 0.564071 | 0.562457 | **0.565422** | P2 |
| 持续故障阶段 | 0.579045 | **0.594575** | 0.592637 | 0.592387 | B5 |

#### V2-5–V2-6：Demo 2.0 与内部发布候选

- Demo 加载四个真实模型和真实测试样本；
- 合同或哈希不匹配时失败关闭；
- 完成 78 项测试、依赖检查、HTTP 健康检查和中文交付材料；
- V2 适合内部演示，但公开发布仍受许可证和作者信息阻塞。

### 6.3 V3：从“传感器可靠度”到“决策风险”

V3 不重新训练 P2 主模型，而是复用 15 个冻结的 fold/seed checkpoint，研究如何决定哪些
预测应该接受、拒绝或告警。

#### V3-1：直接用系统可靠度拒绝

- 正式单元：15/15；
- P2 普通分类确定度 AURC：0.345228；
- P2 系统可靠度 AURC：0.436400；
- 系统可靠度相对普通确定度的错误检测 AUROC 下降 0.218559；
- 两项主比较均 0/5 折胜出。

结论：模态是否受污染的可靠度，不等于当前多标签预测是否出错。

#### V3-2：任务对齐置信度

- 使用 validation 标签拟合 output-only 和 full 逻辑回归选择器；
- full AURC 为 0.358243，仍差于普通确定度 0.345228；
- validation 到 test 的错误检测 AUROC 平均落差为 0.059913；
- 首要比较未通过。

结论：增加传感器状态特征扩大了跨用户过拟合空间，没有形成稳定增量。

#### V3-3：用户分组连续风险

- 使用用户分组交叉拟合和 Ridge 直接预测连续 masked BCE；
- AURC 从 0.345228 降至 0.340077，改善 0.005150；
- 80% 覆盖率 masked BCE 降低 0.005135；
- Macro-F1@80% 提高 0.004558；
- 但错误检测 AUROC 下降 0.019890，因此双主指标仍未同时通过。

结论：一个分数不应同时承担“降低平均连续风险”和“发现任一标签错误”两种不同目标。

#### V3-4：双策略固定阈值

系统最终明确提供两种业务模式：

- `risk_control`：优先降低接受样本的平均 BCE；
- `error_alert`：优先发现至少一个标签出错的样本。

15 个单元、2 种模式、3 个目标覆盖率共产生 90 行正式结果。所有阈值在 validation 冻结。

| 模式 | 目标覆盖率 | 实际覆盖率 | 接受 BCE | Macro-F1 | 拒绝错误召回 |
|---|---:|---:|---:|---:|---:|
| error_alert | 0.80 | 0.8002 | 0.404581 | 0.612379 | 0.249216 |
| error_alert | 0.90 | 0.9015 | 0.421958 | 0.595750 | 0.124835 |
| error_alert | 0.95 | 0.9513 | 0.430660 | 0.586808 | 0.062247 |
| risk_control | 0.80 | 0.7911 | 0.397973 | 0.618170 | 0.257555 |
| risk_control | 0.90 | 0.8935 | 0.417014 | 0.600594 | 0.132794 |
| risk_control | 0.95 | 0.9445 | 0.427343 | 0.590627 | 0.069227 |

- 风险控制专长：3/3 个目标覆盖率通过；
- 错误告警召回专长：0/3 通过；
- 两种模式的覆盖率迁移准备线均通过。

因此 V3 最终可保留 `risk_control`，但不能声称 `error_alert` 达到了预注册的召回优势。

### 6.4 V4-1：最后一次标签级可靠融合

P2 对所有标签共享一组模态权重。V4-1 的假设是：不同标签依赖不同模态，因此把 utility
扩展为“模态 × 标签”可能提高自然缺失 Macro-F1。

实验设计：

- 模型：P2-LC；
- 矩阵：5 个 fold × 3 个 seed，共 15 个单元；
- 从相同 fold/seed 的 P2 精确 warm-start；
- 冻结 P2 编码器、可靠度、β 和分类器；
- 仅训练标签条件 utility 网络；
- epoch 0 允许作为 P2 等价回退点；
- validation 早停和选逐标签阈值；
- test 只由独立评估过程打开。

预注册成功标准：

- 五折等权 Macro-F1 平均增益至少 +0.010；
- 至少 3/5 个 fold 胜出；
- 同时通过 Micro-F1、masked BCE、参数量和延迟安全闸门。

正式结果：

| Fold | P2 | P2-LC | 差值 |
|---:|---:|---:|---:|
| 0 | 0.578557 | 0.578557 | +0.000000 |
| 1 | 0.591786 | 0.591786 | +0.000000 |
| 2 | 0.580867 | 0.580541 | -0.000325 |
| 3 | 0.536749 | 0.538385 | +0.001635 |
| 4 | 0.600462 | 0.601172 | +0.000711 |
| **总体** | **0.577684** | **0.578088** | **+0.000404** |

- 胜出折数：2/5；
- 首要成功判定：未通过；
- Micro-F1 差值：+0.000888，通过安全线；
- masked BCE 差值：+0.000970，通过安全线；
- 总参数量：133,724 → 136,496，增加 2.07%；
- 延迟增加：32.87%；
- 回归测试：106/106；
- 工程完整性验收：通过。

最终解释是：标签级路由偶尔能改善个别 fold，但跨种子和跨用户不稳定，收益远低于预注册标准，
还增加了推理延迟。完整性验收通过不等于模型假设通过，因此 P2-LC 保留为阴性消融，不发布。

## 7. 最终系统怎么选

| 需求 | 推荐选择 | 原因 |
|---|---|---|
| 只追求自然缺失分类点估计 | B5 | V2 自然缺失 Macro-F1 最高 |
| 展示质量、可靠度、utility、拒绝闭环 | P2 | 诊断完整，混合故障均值最高 |
| 控制接受样本的平均风险 | P2 + V3-4 `risk_control` | 3/3 覆盖率专长通过 |
| 错误告警 | 暂不宣称通过 | V3-4 召回假设 0/3 通过 |
| 标签级 P2-LC | 不发布 | V4-1 只提升 0.000404，2/5 折胜出 |

项目对外讲解时，推荐把 P2 作为主模型，因为它体现了项目的完整思想；同时必须诚实说明，B5
在部分纯分类终点更高，P2 的优势主要是可诊断的可靠融合、混合故障表现和风险决策闭环。

## 8. 为什么训练时 CPU 高、GPU 低

模型只有约 13 万参数，单次前向和反向很快。训练早期的主要瓶颈不是 GPU，而是 CPU 上的：

- 在线缺失和污染构造；
- 逐样本随机数与场景调度；
- NumPy 到 Torch 的数据准备；
- 小模型导致 GPU kernel 时间短、等待时间长。

V2-0 的剖析显示污染构造占估算训练 step 的 73.65%。后续通过向量化污染和多实验并行提升
整体吞吐，但不能仅靠增加 batch 或进程把 GPU 利用率强行拉满，否则会加剧 CPU 与内存带宽争抢。

## 9. 工程可信度

项目不仅保存最终指标，还保存：

- 协议锁和执行修正；
- run 登记表与尝试日志；
- checkpoint 合同；
- validation 阈值来源；
- 预测和场景样本哈希；
- 汇总结果来源映射；
- 机器可读验收 JSON；
- 回归测试 XML。

V4-1 还发现原聚合器把冻结后的可训练参数量误标成总参数量。最终从 checkpoint 的完整
`state_dict` 独立复算为 P2 133,724、P2-LC 136,496。该校正只修改元数据，不改变模型、
阈值、预测或科学指标。

## 10. GitHub 中会包含什么

仓库应包含：

- 源代码、配置和测试；
- 中文协议、ADR、阶段报告与答辩材料；
- 聚合 CSV/JSON 和验收证据；
- Demo 代码与不含个人数据的讲解素材。

仓库不会包含：

- ExtraSensory 原始或处理数据；
- 用户级原始记录；
- `.venv-dev`；
- `runs/` 中的大型 checkpoint 和逐样本预测；
- `.pt`、`.pth`、`.ckpt`；
- 临时 pytest 目录。

因此 GitHub 仓库可以审查代码、协议和聚合结论，但不能在没有原始数据与 checkpoint 的情况下
直接还原所有已完成 run。需要完整复现实验时，应按数据使用条款自行准备 ExtraSensory，并重新训练。

## 12. 面试时最重要的回答

### 为什么不只报告最高准确率？

因为多模态系统的价值不只是完整输入时的分数，还包括自然缺失、污染、长期故障、可靠度诊断
和可控拒绝。项目预先冻结成功标准，正结果和负结果都保留，避免事后挑选。

### P2 为什么有价值，但没有全面超过 B5？

B5 的 Sensor Dropout 和污染训练已经是很强的鲁棒分类基线。P2 增加的是 utility、reliability、
system reliability 和拒绝闭环，其主要价值在诊断与决策能力，不是保证所有分类指标都第一。

### V3 最重要的发现是什么？

传感器可靠度与预测错误风险不是同一个概念。连续风险控制和错误告警也是不同目标，应该使用
不同策略，而不是让一个分数同时优化所有需求。

### V4-1 为什么不发布？

它只把 Macro-F1 提高 0.000404，只有 2/5 个 fold 胜出，未达到预注册的 +0.010 和 3/5。
即使安全闸门与工程验收通过，也不能把它包装成模型成功。

### 项目最终亮点是什么？

亮点是把数据防泄漏、多模态质量、可靠度约束、压力测试、选择性预测、协议锁和失败关闭做成
一条完整可审计的研究工程链，并能清楚说明每项改进在哪些条件下有效、在哪些条件下无效。

## 14. 最终结论

RobustSense 的最终结论不是“模型越复杂越好”。B5 证明简单而充分的鲁棒训练很强；P2 证明
可靠度约束能补充诊断与决策能力；V3 证明风险控制与错误告警必须分开；V4-1 则证明标签级
融合的额外复杂度没有带来足够稳定的主终点收益。

因此项目在预先声明的停止规则下结束模型迭代，保留 P2 和通过验证的风险控制策略，并把
P2-LC 作为可信的阴性实验结果。这比只展示一个偶然更高的分数更适合作为面试和研究项目。
