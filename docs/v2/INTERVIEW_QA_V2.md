# RobustSense V2 面试追问库

## 一、问题与数据

### 1. 为什么是多标签而不是多分类？

一个时刻可以同时是“坐着、在室内、在家、使用电脑”，标签不互斥，因此每个标签独立
sigmoid。softmax 会强迫概率竞争，任务定义错误。

### 2. NaN 标签怎么处理？

NaN 表示未知，不当成 0。训练用 target mask 排除未知项，所有 F1、AP、Brier 和风险指标
也只统计已知标签。

### 3. 为什么按用户划分？

随机按行划分会把同一人的习惯和设备特征泄漏到 train/test，得到过于乐观的结果。用户五折
衡量对未见用户的泛化。

### 4. validation 为什么是下一 fold？

它是预先冻结的确定规则，使每个外层 test fold 都有用户互斥 validation，避免运行后挑选。

### 5. 如何证明预处理没有泄漏？

每个 fold 的中位数、IQR、异常统计和类别权重只拟合 train 用户；文件合同保存源 split 和
哈希。test 在训练进程中不构造。

## 二、模型

### 6. B4、B5、P、P2 的最小区别是什么？

B4 是普通内容门控；B5 加整模态 dropout 和污染；P 加五维质量与可靠度辅助学习；P2 把
utility 与 reliability 分开，并用 reliability 结构性约束权重和拒绝。

### 7. 五维质量分别是什么？

是否可用、特征观测比例、异常值比例、绝对稳健 z 均值、绝对稳健 z 最大值。前两项表达
缺失，后三项表达数值异常程度。

### 8. 为什么同时要 utility 和 reliability？

可靠但与当前任务无关的模态不应高权重；很有用但当前损坏的模态也不应高权重。两个概念
混在一个 gate 里难以诊断，也没有单调约束。

### 9. P2 权重公式的直觉？

utility 给基础偏好，`β log(r+ε)` 给可靠度惩罚。r 越低，log 项越负。在 utility 固定时，
可靠度下降不会增加权重。

### 10. β 为什么用 softplus？

要保证 β 始终为正，避免可靠度越低反而奖励权重。softplus 可微且满足正值约束。

### 11. 系统可靠度是什么？

`Σ w_i r_i`，即模型实际采用的模态可靠度加权和。它不是预测正确率，也不是安全概率。

### 12. Sensor Dropout 和普通 Dropout 的区别？

普通 Dropout 随机屏蔽神经元；Sensor Dropout 关闭一个完整模态，模拟传感器不可用，并同步
更新 availability、feature mask 和质量。

## 三、训练与阈值

### 13. 为什么不能统一用 0.5 分类阈值？

15 个标签流行率不同，稀有标签用 0.5 可能几乎不触发。项目在 validation 为每个标签选择
F1 最优网格阈值，冻结后用于 test。

### 14. 拒绝阈值怎么选？

只在 validation 按目标覆盖率选择。test 只报告该工作点的实际覆盖和已接受样本指标，不重调。

### 15. 一致性损失为什么需要 clean/corrupt 两次 forward？

它约束同一语义样本在污染前后的预测不要无必要漂移。代价是训练更慢，这也是 P2 的工程成本。

### 16. reliability target 从哪里来？

训练期故障是已知注入，因此能构造软可靠度目标；自然输入则由 availability 与质量响应形成。
推理时不需要人工故障标签。

## 四、实验与统计

### 17. 为什么要三个随机种子？

单 seed 无法区分方法差异与初始化/批次顺序波动。三个 seed 先在 fold 内聚合，再跨 fold。

### 18. 为什么是 60 个核心单元？

4 个模型 × 5 个外层 fold × 3 个 seed = 60。扩展评估另有 60 个逻辑单元，不重复训练。

### 19. 63-mask 是什么？

六个模态所有非空可用组合，共 `2^6-1=63`。它比随机移除几个模态覆盖更完整。

### 20. 混合故障为什么是 60 个？

选择一个 drop 模态和一个不同的 Gaussian 模态，共 6×5，再乘 σ=1、2，共 60。

### 21. Bootstrap 为什么按用户抽样？

样本行在用户内高度相关。按行抽样会虚增有效样本量；按用户并在外层 fold 内分层更符合
泛化单位。

### 22. P2 是否显著优于 P？

不能这样说。P2-P 自然缺失均值约 +0.0012，但 95% 区间跨 0。可信表达是点估计略高、
统计证据不足。

### 23. 最好的模型到底是谁？

取决于目标。自然缺失、63-mask 和持续故障分类是 B5；混合故障平均是 P2；如果需要可靠度
诊断和拒绝机制，只有 P2 提供完整闭环。

### 24. 为什么复杂 P2 没全面超过 B5？

Sensor Dropout 已是强归纳偏置；质量特征可能与内容编码信息重叠；可靠度辅助目标不完全等同
分类最优；用户与场景规模也限制小差异稳定性。

## 五、工程

### 25. GPU 利用率为什么低？

模型小，CPU 在读取数据、构造质量、执行确定性污染和调度许多小场景，GPU 等待输入。显存
占用和 CUDA 张量证明不是纯 CPU 训练。

### 26. 怎么加速，为什么不直接开更多 worker？

先场景合批，再双任务并行。更多 worker 会争用已满载的 CPU 和内存带宽，且可能破坏 6GB
显存余量。双路实测约减少 26.5% 扩展墙钟时间。

### 27. 如何保证并行不改变科研结果？

每个 worker 仍调用相同单元脚本、使用独立 run 目录；场景、seed、阈值、样本顺序都不变；
主进程单独写登记表；执行 ADR 在启动前锁定。

### 28. 两条 P2 为什么曾显示失败？

产物校验器错误地从 evaluation manifest 读取阈值来源，而权威字段在 thresholds.json。产物
完整、字段为 val。修正先写 ADR 和锁，只重新分类，不重训，也保留原失败尝试。

### 29. Demo 怎么避免伪造？

run 由正式登记表解析；加载时校验 checkpoint、阈值、评估身份、测试 split 与报告哈希。
任何错误都停止，没有随机概率或固定示例回退。

### 30. 如果再升级，你会做什么？

优先加入第二数据集或原始信号验证、做跨设备校准和端侧延迟/功耗实测；模型层面再考虑时序
编码器。先补外部有效性，不急于堆更复杂结构。

## 六、容易说错的话

| 不严谨表述 | 正确表述 |
|---|---|
| P2 显著优于所有基线 | P2 混合故障均值最高；自然主终点区间跨 0 |
| 模型能检测真实硬件故障 | 模型在预计算特征空间故障上评估 |
| system reliability 是正确率 | 它是采用模态的预测可靠度加权和 |
| Demo 是实时手机应用 | Demo 是离线测试特征回放 |
| 37 万样本彼此独立 | 统计抽样单位是用户，行内相关 |
| 缺失标签等于负类 | NaN 是未知，完全从损失和指标排除 |
