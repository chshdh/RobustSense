# ADR-0003：扩展评估合同

- 状态：已接受
- 日期：2026-09-17
- 阶段：V2-2

## 背景

V1 的单点故障矩阵不足以回答任意模态组合、同时缺失与污染、持续故障、选择性预测和
缺失模式捷径等问题。若每个模型各自选择测试样本，或在测试场景上重新选择阈值，模型
差异会与样本差异、调参泄漏混在一起。

## 决策

1. 六模态顺序沿用项目常量：`phone_acc`、`phone_gyro`、`watch_acc`、`location`、
   `audio`、`phone_state`。63-mask 的位序不得重新解释，空 mask 永不进入评估。
2. 每个 fold 先从完整模态测试总体冻结有序样本 ID；B4、B5、P、P2 必须复用同一
   `scenario_sample_sha256`。聚合前执行跨模型哈希一致性检查。
3. 混合故障固定为“有序 drop 一个模态，再对另一个模态施加 Gaussian”，强度只取
   1.0 和 2.0，共 60 个场景。Gaussian 不得落到已经 drop 的模态。
4. 持续 episode 只能在同一用户内构造；相邻时间差超过 90 秒立即断开。故障前、故障中、
   故障后各占一个等长区间，长度取 5、15、30。当前模型仍是逐样本模型，因此这些结果
   只能说明响应轨迹，不能说明模型具有时序推理能力。
5. Mask-only 的 forward API 只接收六维 availability。训练折由外部用户划分提供；测试
   用户内的 availability 置换使用固定 seed，不能跨用户置换。
6. 可靠度校准使用固定分箱；故障检测分数定义为 `1-r_i`。单类、空分箱、空 episode
   阶段和无有效 Bootstrap 重复均保留 `NaN`，不得以 0 填充。
7. Risk-Coverage 按系统可靠度稳定降序选择接受样本。风险为接受样本上的 masked BCE，
   同时报告 Macro-F1/Micro-F1；未知标签不进入风险或分类指标。
8. Bootstrap 在测试用户内有放回抽用户，同一个抽样索引同时作用于两模型。默认 2,000
   次、seed 13，并保存抽样索引哈希和两个源 run ID。
9. 场景清单使用规范 JSONL；数值表使用固定列顺序 CSV；所有图和表的 lineage 必须至少
   包含一个源 run ID。没有真实 run 时只能生成“场景合同”，不得生成或暗示模型结果。

## 后果

- V2-2 可以在正式训练前独立验证场景和指标代码。
- 正式结果只能在后续阶段读取冻结检查点、validation 阈值和同一场景样本哈希后产生。
- 新增或修改场景、阈值来源、聚合规则时，必须创建新协议版本，不能覆盖本协议。
