# RobustSense V2 八分钟口头稿

## 0:00–0:50 研究问题

我的项目叫 RobustSense。它解决的是移动端多源感知中的可靠融合问题。现实里传感器不只会
缺失，还可能继续在线但数据已经异常。如果模型只学习“哪个模态对任务重要”，就可能给一个
高 utility、低可靠度的坏模态很高权重。因此我把问题定义为：在多标签识别中，怎样显式分开
任务 utility 和输入 reliability，并在整体可靠度不足时允许拒绝。

## 0:50–1:40 数据与任务

我使用 ExtraSensory 官方预计算特征，60 名用户、377,346 个样本。六个工程模态是手机
加速度、手机陀螺仪、手表加速度、位置、音频和手机状态。任务同时预测 15 个活动和情境，
所以用逐标签 sigmoid。原始标签里的 NaN 是未知，不是负类，必须从损失和指标中 mask。

外层使用官方用户五折。当前 fold 是 test，下一 fold 是 validation，其余是 train。每个
fold 单独拟合训练中位数、IQR、异常统计和类别权重。逐标签分类阈值以及 P2 拒绝阈值都只
在 validation 选，test 在 checkpoint 和阈值冻结后才由独立进程打开。

## 1:40–3:05 模型设计

我保留三个逐级增强的基线。B4 是普通内容门控；B5 加 Sensor Dropout 和训练期 Gaussian、
偏置、尺度污染；P 再加入每模态五维质量和可靠度辅助损失。五维质量分别是是否可用、观测
比例、异常比例、稳健 z 分数绝对值均值和最大值。这些量从当前输入和训练统计得到，不需要
知道人工故障标签。

P2 的关键是结构性拆分。每个模态编码后，一条支路输出任务 utility u_i，另一条输出
reliability r_i。最终权重是在可用模态上计算 softmax(u_i + beta log(r_i + epsilon))。
因此在 utility 不变时，可靠度下降不会增加权重。beta 用 softplus 参数化，始终为正。
系统可靠度是各模态可靠度按最终权重的加权和。低于验证集阈值时输出拒绝。

训练损失除了带 mask 的加权 BCE，还有可靠度回归、可靠度排序和干净/污染一致性。Sensor
Dropout 关闭整个模态，不等同普通神经元 Dropout。

## 3:05–4:20 实验设计

正式核心矩阵是 B4、B5、P、P2，五个 fold、三个 seed，一共 60 个单元。seed 13 的
20 个单元通过合同复用，seed 29 和 47 新训练 40 个。聚合顺序固定为先在每个 fold 内聚合
三个 seed，再跨五个 fold。

扩展评估对同一完整模态测试样本运行 63 个非空 availability mask、60 个“drop 一个模态
同时 Gaussian 污染另一个”的混合故障，以及长度 5、15、30 的持续故障。自然缺失主比较
是 P2 对 P，以用户为抽样单位做 2000 次 fold 分层配对 Bootstrap。

所有 run 都有协议哈希、登记状态、尝试日志、checkpoint 合同、样本哈希和来源映射。最终
60 个核心单元和 60 个扩展单元全部成功。

## 4:20–5:40 结果与诚实边界

自然缺失 Macro-F1：B4 是 0.5651，B5 是 0.5786，P 是 0.5767，P2 是 0.5777。
最高的是 B5，不是 P2。P2 相对 P 的用户级 Bootstrap 平均差约 +0.0012，95% 区间从
-0.0017 到 +0.0043，跨 0，所以不能宣称稳定提升。

63-mask 平均也是 B5 最高，0.5178；P2 是 0.5168。混合故障平均 P2 最高，0.5654，
相对 B5 只高约 0.0014。持续故障 fault 阶段又是 B5 最高。

因此我的结论不是“复杂模型全面碾压”，而是：简单的 Sensor Dropout 基线非常强；P2 在
混合故障和诊断、拒绝能力上提供额外价值，但分类主终点只与 B5/P 相近。这是项目里最值得
讲的负结果，因为它证明我没有为了展示而选择性报告。

## 5:40–6:35 性能优化

训练时我发现 GPU 利用率只有约 20%，CPU 很高。检查显存和张量设备后确认确实在用 CUDA，
但模型小，CPU 在做数据读取、质量刷新和大量确定性场景构造，GPU 经常等待。

我先把多个场景合并为 GPU 批次，再通过独立 ADR 把任务改成双路并行。登记表只由主控制器
写，worker 写不同 run 目录；显存不足就失败，不静默改协议。扩展单元串行基准约 90 秒，
剩余 59 个双路完成约 65 分钟，估算墙钟减少约 26.5%。没有接近两倍，是因为 CPU 和内存
带宽仍然竞争，这与瓶颈判断一致。

## 6:35–7:30 Demo 2.0

Demo 是离线预计算特征回放，不是实时传感器。页面从 V2-4 登记表解析 B4/B5/P/P2 的真实
run，强制四模型共享 fold、seed、测试 split 和样本。可以关闭模态并注入 Gaussian、偏置
或尺度错误，展示预测变化、五维质量、可靠度、P2 utility、最终权重、系统可靠度与拒绝。

另有持续故障 pre-fault-post 时间轴、63-mask 和混合故障聚合背景。所有图来自真实报告；
checkpoint、阈值或哈希不匹配时页面停止，没有随机预测回退。

## 7:30–8:00 局限与总结

局限包括：单一数据集、预计算特征、特征空间故障、用户数有限、没有跨设备或手机端功耗
实测。拒绝也不是安全认证。

这个项目对我最重要的收获是把建模、科研有效性和工程治理连起来：不仅训练模型，还证明
没有数据泄漏，保留失败与修正历史，做不确定性统计，并让每个 Demo 数字回到真实产物。
