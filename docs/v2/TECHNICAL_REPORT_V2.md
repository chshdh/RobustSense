# RobustSense V2 技术报告

## 摘要

RobustSense V2 面向多源移动感知中的两个现实问题：模态会自然缺失，仍然在线的模态也可能
产生异常、漂移或尺度错误。项目基于 ExtraSensory 的手机、手表、位置、音频和设备状态
预计算特征，完成用户独立五折、多标签上下文识别。V2 在原有门控融合基线上增加质量特征、
显式可靠度、任务 utility、可靠度约束权重和选择性预测，并通过 5 个外层 fold、3 个随机
种子、4 个核心模型、63 种非空模态组合、60 种混合故障和持续故障 episode 进行评估。

核心 60 个训练/复用单元与 60 个扩展评估单元全部成功。自然缺失 Macro-F1 上 B5 为
0.578605，P2 为 0.577684，P 为 0.576678，B4 为 0.565135。P2 相对 P 的用户级配对
Bootstrap 均值为 +0.001184，95% 区间为 [-0.001732, 0.004345]，不能宣称稳定显著提升。
混合故障均值上 P2 最高（0.565422），但 B5 在 63-mask 平均和持续故障分类终点上最高。
因此项目的可信结论是：显式可靠度约束带来更完整的诊断、拒绝和部分受控故障优势，而不是
“新模型在所有指标上全面领先”。

## 1. 问题定义

输入样本由六个工程模态构成：手机加速度、手机陀螺仪、手表加速度、位置、音频、手机状态。
目标是同时预测 15 个活动与情境标签，因此输出使用逐标签 sigmoid，而不是互斥 softmax。
源标签中的 `NaN` 表示未知；未知标签既不进入损失，也不进入指标分母。

每个模态具有三类状态：自然不可用、可用且正常、可用但受污染。普通门控模型只能从内容
学习“重要性”，无法保证受损模态的权重下降。V2 的核心问题是：能否把“对任务有用”与
“当前可信”拆开，并在可信度不足时允许系统拒绝。

## 2. 数据与防泄漏

ExtraSensory 官方预计算特征版本包含 60 名用户、377,346 个样本。外层采用官方用户五折：
当前 fold 只作为 test，下一 fold 作为 validation，其余三个 fold 为 train。每个外层 fold
独立拟合训练特征中位数、IQR、异常统计、类别权重；逐标签分类阈值只在 validation 的
0.05–0.95 网格选择。P2 的拒绝阈值也只在 validation 按目标覆盖率选择。test 直到
checkpoint 和阈值冻结后才由独立评估进程打开。

## 3. 模型

| ID | 模型 | 关键差异 |
|---|---|---|
| B4 | Gated Fusion | 内容编码后学习模态竞争权重 |
| B5 | Robust Gated Fusion | B4 + Sensor Dropout 与训练期污染 |
| P | Quality-Aware Fusion | B5 + 五维质量与可靠度辅助学习，可靠度参与普通门控 |
| P2 | Reliability-Constrained Fusion | 独立 utility 与可靠度，可靠度显式约束权重，并支持拒绝 |

每个模态的五维质量为：是否可用、特征观测比例、异常值比例、稳健标准分绝对值均值、稳健
标准分绝对值最大值。统计基准只由训练用户拟合，推理时不需要人工故障类型。

P2 对第 i 个模态产生任务 utility `u_i` 与可靠度 `r_i∈[0,1]`，并计算：

```text
w_i = softmax(u_i + β log(r_i + ε))，仅在可用模态上归一化
R_system = Σ_i w_i r_i
```

`β` 通过 softplus 参数化，始终为正；不可用模态权重严格为 0。训练损失包含分类、可靠度
回归、可靠度排序和干净/污染一致性项。系统可靠度低于 validation 冻结阈值时，P2 输出拒绝。

## 4. 故障与评估合同

训练期 Sensor Dropout 关闭整个模态，并对保留模态注入 Gaussian、偏置或尺度污染。正式
扩展评估使用完整模态测试子集，在所有模型之间冻结同一有序样本：

- 63 个非空 availability mask；
- 60 个“drop 一个模态 + Gaussian 污染另一个模态”的组合；
- 长度 5、15、30 的 drop 或 Gaussian σ=2 持续故障；
- P2 Risk-Coverage 与验证集拒绝工作点；
- 自然缺失 P2-P 用户级配对 Bootstrap 2,000 次。

统计顺序固定为先在每个 fold 内聚合三个 seed，再跨五个 fold 计算均值和样本标准差。扩展
场景不保存全量逐场景预测，只保存聚合、诊断、样本哈希和 lineage。

## 5. 主要结果

### 5.1 自然缺失

| 模型 | Macro-F1 均值 | fold 标准差 |
|---|---:|---:|
| B4 | 0.565135 | 0.027811 |
| B5 | **0.578605** | 0.024325 |
| P | 0.576678 | 0.025427 |
| P2 | 0.577684 | 0.024516 |

P2 的点估计略高于 P，但 95% Bootstrap 区间跨 0。最合理的解释是二者自然缺失分类能力
接近，当前样本量与用户差异不足以支持稳定优势声明。

### 5.2 63-mask

63 个组合等权平均为 B4 0.485345、B5 0.517801、P 0.516258、P2 0.516783。仅一个
模态可用时 P 略高；三个及以上模态时 B5 均值最高。Sensor Dropout 本身已经形成很强基线。

### 5.3 混合故障

混合故障均值为 B4 0.544741、B5 0.564071、P 0.562457、P2 0.565422。P2 在 σ=1
和 σ=2 两组均最高，但领先幅度较小；这是一项描述性受控场景结果。

### 5.4 持续故障

故障阶段均值为 B4 0.579045、B5 0.594575、P 0.592637、P2 0.592387。B5 在分类
终点最高。P 和 P2 还提供真实可靠度时间响应，可报告检测延迟与恢复步数；B4/B5 不产生
该信号，因此不会用伪 0 填充。

## 6. Demo 2.0

Streamlit Demo 通过 V2-4 登记表加载四个真实 checkpoint，并验证 checkpoint、标签、测试
split、分类阈值、P2 拒绝阈值和扩展报告哈希。同一样本可关闭模态并注入特征空间故障，
页面展示预测变化、五维质量、可靠度、P2 utility、最终权重、系统可靠度和接受/拒绝。
所有合同失败均直接停止，没有随机预测回退。页面明确属于离线预计算特征回放。

## 7. 工程与可复现性

项目保留协议锁、run 登记表、尝试表、错误日志、artifact SHA-256 和来源映射。核心训练曾
发现 GPU 利用率低而 CPU 较高，原因是小模型、CPU 数据构造和频繁场景调度。通过保持数值
语义不变的向量化场景批处理与双任务并行，降低墙钟时间；并行修正只读取时间和资源指标，
不读取模型成绩。

最终验收为 60/60 核心、60/60 扩展、78/78 测试、813/813 V1 文件、`pip check` 和
Streamlit 健康检查全部通过。

## 8. 限制

1. 输入是官方预计算特征，不是原始传感器时序；
2. 人工污染发生在标准化特征空间，不能等同真实硬件故障；
3. 只有 ExtraSensory 一个数据集，跨设备与跨数据集泛化尚未验证；
4. 五折只有 60 名用户，P2-P 的小差异具有明显不确定性；
5. 拒绝机制只说明覆盖率—风险取舍，不自动等同安全保证；
6. 当前 Demo 是离线回放，不是手机端实时部署；
7. 许可证和真实作者信息尚未由项目所有者确定，不能直接公开发布。

## 9. 结论

RobustSense V2 的主要价值不是制造一个夸大的“全面 SOTA”结果，而是把多模态质量、可靠度、
权重和拒绝机制做成可训练、可验证、可解释、可追溯的完整工程。结果显示简单鲁棒门控仍是
强基线，P2 在混合故障与诊断能力上有价值，但自然缺失主终点没有可靠显著优势。这种正负
结果都能解释的边界，构成项目在面试中的可信度。
