# ADR-0004：seed 13 五折与消融治理

- 状态：已接受
- 日期：2026-09-17
- 阶段：V2-3

## 背景

V2-3 首次打开正式 test，因此训练矩阵、消融定义、阈值来源、失败重试和后续多种子选择
必须在首个 test 结果出现前冻结。性能基线同时表明逐样本污染是 CPU 瓶颈，而盲目增大
batch 虽能提高吞吐，却会减少优化步数并破坏与 V1 P 的训练公平性。

## 决策

1. 正式矩阵固定为 P2、P2-A1、P2-A2、P2-A3、P2-A4 × 五 fold × seed 13，
   共 25 个注册单元，不跳过任何 fold 或变体。
2. 训练预算沿用 V1 credible：最多 80 epoch、batch 512、AdamW、学习率 0.001、
   weight decay 0.0001、梯度裁剪 5、patience 10。尽管预检中大 batch 吞吐更高，仍保留
   batch 512 以避免改变优化轨迹和比较条件。
3. 训练污染继续按 `seed|epoch|user|timestamp|view` 产生完全相同的随机抽样；只将大量
   小切片写入改成按模态批量张量写入。三类噪声均与旧实现逐元素、逐元数据精确相等。
4. 消融定义冻结如下：A1 只移除可靠度对融合权重的约束；A2 只移除 ranking loss；
   A3 只移除 ReliabilityNet 的五维质量输入；A4 只移除推理时选择性拒绝。
5. A4 不改变训练目标或模型参数，因此不重复训练。它从同 fold/seed 的 P2 检查点派生，
   保存源 run 和参数张量哈希，并生成独立 checkpoint 合同与 run ID。A4 不保存拒绝阈值，
   也不输出 Risk-Coverage。这仍计为一个预先注册的实验单元，而不是跳过实验。
6. 训练函数只能构造 train/validation 数据集。只有最佳 checkpoint、逐标签分类阈值和
   拒绝阈值全部由 validation 冻结后，独立评估进程才打开 test。
7. 本阶段正式评估只报告自然缺失。63-mask、混合/持续故障和多种子扩展仍属于 V2-4，
   防止在 seed 13 中期结果出现后修改压力测试协议。
8. 运行注册表和 attempt ledger 放在 `reports/v2/`，日志放在 `runs/v2/`；V1 的 registry、
   run 和报告不得修改。中断单元转为 failed，只允许明确重试，成功单元不重跑。
9. 后续最多扩展两个消融变体。选择只读取五折 validation Macro-F1，以相对 P2 的逐 fold
   绝对差均值排序，取前两名，同分按变体 ID。选择函数在接口上不接收 test 指标。

## 后果

- 25 个状态能完整审计，失败和重试不会被覆盖。
- P2 与 V1 P 保持相同主要训练预算；优化收益来自数值等价实现，而非改变 batch。
- A4 避免五次无意义的重复训练，同时通过参数哈希证明干预只发生在推理决策层。
- test 结果无论好坏都不能反向修改本协议；任何必要修改必须建立新 ADR 和新锁。
