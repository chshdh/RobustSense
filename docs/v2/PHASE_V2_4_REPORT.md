## 1. 阶段结论

V2-4 已完成 B4、B5、P、P2 的五折、三随机种子核心矩阵，以及对应的扩展压力评估。
核心登记表和扩展登记表均为 `60/60 success`，没有待运行、运行中或真实失败单元。20 个
seed 13 单元按冻结合同复用，40 个 seed 29/47 单元新训练；扩展评估读取相同的 60 个
checkpoint，不重新训练或调整阈值。

结果不支持“P2 在所有条件下都优于基线”的强结论。B5 在自然缺失、63-mask 平均和持续
故障阶段表现最高；P2 在混合故障平均上最高，并提供 B4/B5/P 不具备的可靠度约束、系统
可靠度和验证集拒绝机制。自然缺失下 P2 相对 P 的用户级配对 Bootstrap 区间跨 0，因此
只能表述为点估计略高，不能宣称统计上可靠的全面提升。

## 2. 核心矩阵

```text
模型：B4、B5、P、P2
外层 fold：0、1、2、3、4
随机种子：13、29、47
逻辑单元：4 × 5 × 3 = 60
最终状态：60 success，0 failed，0 running，0 pending
聚合顺序：先在每个 fold 内聚合三个 seed，再跨五个 fold 聚合
```

自然缺失测试集 Macro-F1：

| 模型 | 五折均值 | fold 间样本标准差 |
|---|---:|---:|
| B4 | 0.565135 | 0.027811 |
| B5 | **0.578605** | 0.024325 |
| P | 0.576678 | 0.025427 |
| P2 | 0.577684 | 0.024516 |

P2 相对 P 的表格点差为 `+0.001006`。按用户、外层 fold、seed、时间戳和标签配对的
2,000 次 Bootstrap 得到：

- 平均差 `P2 - P = +0.001184`；
- 95% 区间 `[-0.001732, 0.004345]`；
- 有效重复 `2000/2000`；
- 抽样种子 `2404`；
- 区间跨 0，不能拒绝“二者在该终点上没有稳定差异”。

## 3. 扩展压力评估

每个核心单元均使用同一完整模态测试总体和相同有序样本，执行 63 个非空模态 mask、
60 个混合故障和 12 个持续故障定义。跨模型样本合同检查为 `true`，五个外层 fold 分别
保存一个冻结的样本哈希。

### 3.1 63-mask

对 63 个 mask 的 Macro-F1 等权平均：

| 模型 | 平均 Macro-F1 |
|---|---:|
| B4 | 0.485345 |
| B5 | **0.517801** |
| P | 0.516258 |
| P2 | 0.516783 |

随着可用模态数从 1 增加到 6，所有模型整体上升。仅一个模态可用时，P 的平均值最高
（0.395684）；三个及以上模态时 B5 的均值最高。该结果说明显式质量与可靠度并没有在
所有缺失组合上形成统一优势，模态内容建模和 Sensor Dropout 仍然是很强的基线。

### 3.2 混合故障

对“丢弃一个模态，同时向另一个模态注入 Gaussian 噪声”的 60 个场景等权平均：

| 模型 | 平均 Macro-F1 |
|---|---:|
| B4 | 0.544741 |
| B5 | 0.564071 |
| P | 0.562457 |
| P2 | **0.565422** |

P2 相对 P 为 `+0.002965`，相对 B5 为 `+0.001351`。在 `sigma=1` 和 `sigma=2` 两组中，
P2 的平均值都最高；这属于受控场景的描述性结果，不替代用户级配对显著性结论。

### 3.3 持续故障

持续故障 `fault` 阶段的 Macro-F1 平均：

| 模型 | 平均 Macro-F1 |
|---|---:|
| B4 | 0.579045 |
| B5 | **0.594575** |
| P | 0.592637 |
| P2 | 0.592387 |

B5 在 drop 和 Gaussian sigma 2 两类持续故障的 fault 阶段均最高。P2 的价值主要体现在
可解释可靠度与拒绝行为，而不是该分类终点上的绝对领先。

## 4. 选择性预测边界

P2 的分类阈值和拒绝阈值均只由 validation 选择。每个正式 P2 run 保存
`abstention_threshold.json`、`risk_coverage.json` 和 test 强制/选择性两套指标。测试集只在
checkpoint 和两个阈值冻结后由独立评估进程打开。Risk-Coverage 曲线用于展示覆盖率与风险
的取舍，不能在 test 上重新选择工作点。

## 5. 执行修正与审计记录

训练和评估数值协议没有在运行后修改。为缩短墙钟时间，核心训练与扩展评估分别通过独立
ADR 冻结为双任务并行，主控制器保持登记表单写入。两条 P2 核心单元曾因校验器错误读取
`evaluation_manifest.threshold_source_split` 而被误记失败；权威字段实际位于
`thresholds.json.source_split` 且值为 `val`。修正前先写入 ADR 和哈希锁，随后只重分类完整
产物，没有重训、删除失败历史或根据性能结果作决定。
