# ADR-0005：V2-4 多种子复用与压力评估治理

- 状态：已接受并纳入正式协议锁
- 日期：2026-09-18
- 关联阶段：V2-4

## 背景

V2-4 要形成 B4、B5、P、P2 的五折三种子核心矩阵，并运行 63-mask、混合故障、持续
故障和用户级配对 Bootstrap。V1 已有 B4/B5/P 的 seed 13 五折，V2-3 已有 P2 的
seed 13 五折；直接重复训练会浪费时间，也会模糊“复用”与“重新训练”的边界。

## 决策

1. 核心矩阵固定为模型 `{B4,B5,P,P2}`、folds `{0,1,2,3,4}`、seeds
   `{13,29,47}`，共 60 个逻辑单元。
2. seed 13 的 20 个单元只在数据、预处理、模型、训练超参数、阈值来源和 checkpoint
   合同全部匹配后复用；复用清单在首个 V2-4 test 前生成并锁定。
3. seeds 29、47 补跑 40 个训练单元。B4/B5/P 复用冻结的 V1 训练实现，P2 复用经过
   V2-3 验证的训练语义，并写入独立 V2-4 run 目录。
4. P2-A3、P2-A1 是由 V2-3 validation 规则选出的可选扩展消融，单独登记 20 个单元，
   不计入 60 个核心验收单元。
5. 扩展压力测试使用 V2-2 已冻结的 63 masks、60 mixed failures 和持续 episode 合同。
   扩展场景默认只保存指标、诊断和样本哈希，不保存每个场景的全量逐样本预测，以控制
   磁盘占用；自然缺失预测仍完整保存，用于用户级配对 Bootstrap。
   为提升 GPU 利用率，每个推理批次合并 8 个独立场景；这只改变执行调度，不改变
   corruption、样本、阈值或指标定义。
6. 三种子聚合先在每个 `fold × model × scenario` 内聚合 seeds，再跨五个 fold 聚合；
   不把 15 个 run 当作 15 个独立用户数据集。

## 后果

- 复用可以节省 20 次重复训练，同时保留可审计来源；
- 新训练、复用和可选消融在注册表中可区分；
- test 结果不能决定复用合同、场景集合、Bootstrap 次数或可选消融名单；
- 若任一复用合同不匹配，单元必须转为待训练或阻断协议锁，不能强行复用。
