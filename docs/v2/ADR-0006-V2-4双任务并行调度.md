# ADR-0006：V2-4 双任务并行调度

- 状态：已接受，首次并行启动前冻结
- 日期：2026-09-18
- 类型：仅执行调度补充，不修改实验设计
- 父协议：V2-4，`35035f18ccb129c1f3b5d8b70f724d9059bf4f5d433259ba586b477d30bd9d34`

## 背景

V2-4 串行运行两个新增单元后，观测到单任务 GPU 利用率约 8%–36%、显存约
1.5/6GB、CPU 总占用约 60%、磁盘占用低于 1%。这些观测只涉及资源和耗时，没有使用
Macro-F1、测试标签或模型间性能差异。小模型的 CPU 数据准备和串行调度限制了墙钟速度。

## 决策

1. 核心矩阵允许最多两个彼此独立的 `fold × seed × model` 单元并行。
2. 每个 worker 仍调用 V2-4 已锁定的单元训练与独立 test 评估入口；不修改数据、模型、
   batch size、数值精度、优化器、早停、阈值或聚合规则。
3. 只有父调度器可以更新注册表和追加 attempt；worker 不接触注册表，避免并发覆盖。
4. 每个单元使用独立 run 目录和独立日志；失败单元保留并登记，不进入最终聚合。
5. 原串行控制器在当前 P/fold0/seed29 子训练继续运行时停止，避免启动下一个单元；该
   单元完成训练后由独立评估命令收尾，再由并行调度器接管剩余 pending 单元。
   并行调度器将这个已登记的 running 单元作为第一个 worker 接管，按冻结状态文件轮询，
   同时只启动一个新的 pending 单元，因此任何时刻仍不超过两个训练/评估单元。

## 科研影响

并发只改变不同独立实验的时间重叠，不改变单个实验的计算图或输入。采用该补充的依据是
资源利用率与墙钟时间，而非已出现的测试性能，因此不会产生按测试结果调整协议的问题。
父协议锁保持原样；本补充使用单独哈希和审计记录。
