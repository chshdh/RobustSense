# RobustSense V2 两分钟口头稿

我的项目叫 RobustSense，研究多模态移动感知在传感器缺失或异常时如何保持可靠。

数据使用 ExtraSensory 官方预计算特征，共 60 名用户、37 万多条样本，包含手机加速度、
陀螺仪、手表、位置、音频和手机状态六个模态，要同时预测 15 个活动和情境标签。

我先建立三个基线：普通门控 B4、加入 Sensor Dropout 和训练期污染的 B5，以及带五维质量
和可靠度学习的 P。升级模型 P2 把两个概念拆开：utility 表示模态对当前任务有没有用，
reliability 表示当前输入是否可信。最终权重由 utility 加上可靠度约束得到，再加权形成系统
可靠度；低于只在验证集选择的阈值时，系统可以拒绝。

实验严格按用户五折，预处理、类别权重和阈值都不接触测试用户。正式矩阵是四个模型、
五个 fold、三个随机种子，共 60 个核心单元；还对每个单元评估 63 种模态组合、60 种混合
故障和持续故障，另外做 2000 次用户级配对 Bootstrap。核心和扩展各 60 个单元全部成功。

结果很有意思：自然缺失和持续故障分类上，简单的鲁棒门控 B5 仍然最好；P2 在混合故障
平均上最高，但自然缺失相对 P 的 Bootstrap 区间跨 0，所以我不会宣称全面提升。P2 真正
新增的价值是 utility、可靠度、系统可靠度、Risk-Coverage 和失败时拒绝，形成了可解释、
可审计的决策链。

工程上我还解决了 GPU 利用率低的问题。定位后发现瓶颈主要在 CPU 场景构造而非 GPU 计算，
于是做场景合批和双任务并行，在不改实验语义的前提下把扩展评估墙钟时间缩短约 26.5%。

最后我做了一个完全读取真实 checkpoint 的离线 Demo：四模型同样本对比，展示五维质量、
可靠度、utility、权重和拒绝状态；任何产物不匹配都会失败关闭，没有随机预测回退。
