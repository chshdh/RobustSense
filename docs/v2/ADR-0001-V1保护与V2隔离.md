# ADR-0001：保护 V1 并隔离 V2

- 状态：已接受
- 日期：2026-09-17
- 决策阶段：Phase V2-0

## 背景

V1 已完成 60/60 个可信实验、6 个开发消融、Phase 7 审计和面试材料。V2 将继续修改共享
训练代码、加入 P2 和更严格的可靠性评估。如果沿用原有配置名、run ID 或报告目录，任何
一次误写都会让 V1 结果失去可追溯性。

当前仓库存在 `.git`，但 `main` 尚无任何 commit。因此现阶段不能把 Git tag 或 commit
当作 V1 唯一版本锚点，文件哈希清单是实际的权威版本证据。

## 决策

1. V1 的配置、`runs/`、报告、协议锁和现有数据清单视为只读。
2. V2 分别使用 `configs/v2/`、`runs/v2/`、`reports/v2/` 和 `docs/v2/`。
3. `reports/v2/v1_baseline_manifest.json` 冻结 V1 配置、协议、数据清单、报告、图表、
   检查点和 compact run 身份文件的 SHA-256。
4. 约 7.25 GiB 的大型 Parquet 预测/诊断文件不重复逐个哈希；它们由冻结的 run 身份文件、
   评估清单和权威聚合报告约束，并且 V2 不允许覆写 V1 run 目录。
5. `reports/v2/phase_v2_0_protocol_lock.json` 只锁定 V2-0 的保护规则和性能基线协议。
   P2 结构与正式实验矩阵必须在后续阶段形成新版本锁，不能静默改写本锁。
6. 共享代码修改后必须先运行 V1 测试、V1 清单校验和报告双重重建；任何哈希变化都必须
   修复，或通过新的 ADR 明确解释并升级协议版本。

## 后果

V2 可以复用 V1 的数据与结果作为对照，但不会把升级实验混入 V1。由于当前没有 Git
commit，清单比 tag 更重要；建立正式版本历史仍是后续发布治理任务，不在本阶段伪造提交。
