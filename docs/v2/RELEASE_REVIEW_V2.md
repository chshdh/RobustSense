# RobustSense V2 发布审查

## 当前结论

项目适合本地展示、面试演示和私有仓库评审。尚不满足直接公开发布条件，原因不是实验失败，
而是许可证与作者身份仍需项目所有者决策。

## 已通过

- V2 核心 60/60、扩展 60/60 success；
- 78 项测试、Ruff、依赖检查通过；
- V1 冻结清单 813/813 文件通过；
- Demo 真实四模型回放与 HTTP 健康检查通过；
- 训练/验证/测试边界、阈值来源、样本哈希和 run lineage 可审计；
- 文档使用中文，不制作 PPT；
- 数据目录、原始归档、处理数据和大 checkpoint 不应随仓库公开提交。

## 公开前必须完成

1. 选择明确的代码许可证，替换当前未授权占位 `LICENSE`；
2. 在 `CITATION.cff` 填写真实作者、联系方式和版本信息；
3. 复核 ExtraSensory 数据许可与再分发边界，公开仓库只保留下载说明；
4. 检查 Git 历史中没有原始用户 ID、数据归档、模型大文件和绝对本机路径；
5. 决定 checkpoint 是否发布，并为每个文件提供来源、哈希与用途；
6. 若公开 Demo，增加资源上限、访问日志政策和隐私声明。

## 数据与隐私

ExtraSensory 涉及行为与位置情境。Demo 只显示用户 ID 哈希，不展示原始 UUID。哈希用于页面
区分，不构成匿名化安全保证。公开材料不得附带逐样本预测或可反查个体的时间序列。

## 模型声明

不得使用“SOTA”“真实硬件故障检测”“安全可靠性保证”或“实时手机部署”等未经验证表述。
推荐结论是：P2 提供可靠度约束与拒绝闭环，在混合特征故障上有小幅描述性优势，但自然
缺失主终点没有统计上稳定的全面提升。
