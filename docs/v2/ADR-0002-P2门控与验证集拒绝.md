# ADR-0002：P2 约束门控、排序视图与验证集拒绝

- 状态：已接受
- 日期：2026-09-17
- 决策阶段：Phase V2-1

## 背景

V1 的 P 把内容、质量和可靠度一起送入自由 Gate，导致 `reliability` 不必单调影响最终权重。
V2 需要区分“模态对任务是否有用”和“模态当前是否可信”，同时在输入整体不可靠时允许拒绝，
而不是把拒绝解释成所有标签为负。

## 决策

1. 每个模态保留独立编码器和 ReliabilityNet，新增只读取编码 `h_i` 的 UtilityNet。
2. 最终分数固定为 `u_i + beta * log(r_i + epsilon)`；`beta` 通过
   `softplus(raw_beta) + epsilon` 参数化，训练和推理使用同一公式。
3. 不可用模态仍由 masked softmax 精确归零；全部不可用立即报错。
4. 系统可靠度固定为 `sum_i(w_i * r_i)`，不再训练另一套系统分数网络。
5. 排序损失使用同一样本/模态的 clean 视图和训练污染视图；只在
   `artificial_fault=True` 的位置比较。故障类型、强度和 target 只参与监督，不进入 forward。
6. clean 分支在 P2 ranking 训练中保留梯度；一致性损失仍对 clean logits detach，避免把污染
   预测当作反向目标修改 clean 软标签。
7. 拒绝阈值取 validation 系统可靠度的观测分位点，选择满足目标覆盖率的最高观测阈值；
   ties 保守地多接受。test 只能读取保存的阈值。
8. P2 开发训练只产生 train/validation 产物，不自动打开 test。正式测试评估属于后续冻结阶段。

## 后果

P2 的可靠度降低在 utility 固定时不可能让本模态权重上升，解释性比自由 Gate 更强。
代价是每个 batch 需要 clean/corrupt 两次 forward，开发训练更慢；Phase V2-0 已证明主要瓶颈
仍是 CPU 污染逻辑，性能优化必须在保持确定性和损失语义的前提下另行实施。
